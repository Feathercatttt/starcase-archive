# 星匣维护与发布

项目根目录：`D:/软件/DSH 大肥鱼专用/星匣`。先阅读这里的 `AGENTS.md`、`README.md` 和相关源文件。不要把长对话里旅人手札的旧要求自动套入这个新软件。

当前交接基线：2026-10-19，v0.1.1，个人资料库，暂不区分主持人与玩家。Windows、Android、单文件 HTML 均有独立发布配置。用户已授权发布独立公开仓库 `Feathercatttt/starcase-archive`，`src/native.js` 的 `UPDATE_PUBLISHED=true`；发布完成与否以远端 release、签名清单及验证记录为准。后续接手先核实实际线上状态。

## 用户确定的产品方向

- 四个入口：灵感盒、DND 世界观、COC 模组、规则与资料。灵感一句话即可入库，标签和分组可以以后补。
- 世界观收植物、地点、人物、势力和设定。规则资料区收私设规则、魔法物品、怪物；COC 与 DND 使用各自模板，不强行套用对方数值。
- 标准字段和自定义空间同样重要。条目可留来源原文、修订号、校对状态和稳定关联，方便 AI 整理与后续插件读取。
- 初版先确认模板和操作方式。不能把四份飞书小样本说成已迁移整座知识库。
- 阅读优先：纸页与书脊配色、清晰中文、编辑分组可折叠、空字段在阅读页隐藏。遵循项目 `DESIGN.md`；手机使用紧凑底部导航。

## 按任务读取

- 修改界面、模板、保存逻辑、整理资料：读 [结构与数据](references/architecture-data.md)。改模板时一起维护导出合同，保留旧 ID 和未知字段。
- 生成 EXE / APK、处理启动或互通问题、验证修复：读 [构建与验证](references/build-test.md)。使用与改动相关的检查，报告真实验证范围。
- 上传 GitHub、启用在线更新、发布新版和镜像排错：读 [GitHub 发布与更新](references/github-release.md)。这包含本地准备脚本、固定附件名、签名协议和发布后读取验证。

## 接手与完成

先检查当前文件和未完成改动，定位问题再修改。`src/` 为源，`outputs/` 为生成结果。别通过重跑一次性移植脚本覆盖正在维护的原生代码。

数据兼容优先：保持 `com.starcase.archive`、`starcase-archive-v1`、`StarcaseArchive`、稳定条目 ID 与既有签名身份。修改数据结构要有迁移和旧包导入验证；用户原始规则不可用官方规则或推测值补齐。

功能改完后交付实际文件、关键验证结果和未验证部分。模板整理、本地构建、模拟器测试、线上发布、实体手机验收是不同状态。新需求涉及发布时沿用本轮已有授权，不把 skill 的存在当成再次确认的理由。
